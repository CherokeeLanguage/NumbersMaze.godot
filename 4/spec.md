# Spec — AGENTS.md agent notes + .gitignore editor-cache hygiene

NumbersMaze.godot#4 · feature/agents-md · filed 2026-11-10

## Problem

Future OpenCode sessions start with zero repo-specific guidance. The repo's
non-obvious facts — Godot **3.x** target on a machine whose newest editor
binary is Godot 4.x, committed editor cache, autoload naming discipline, the
`plist.txt` sound-effect registration convention, export include/exclude
filters — each cost multi-file investigation to recover, and one of them (the
Godot-4 editor cache) actively misleads: the committed `.godot/` directory
contains Godot-4-era cache (`.ctex` textures, `uid_cache.bin`,
`.oggvorbisstr` audio) sitting inside a Godot 3.x project (`project.godot`
`config_version=4`), churns in `git status` after every editor session, and
pollutes functional diffs.

Second, observed defect: `git ls-files -i -c --exclude-standard` currently
lists **6 tracked files that match active ignore patterns**. `.godot/` is not
yet among them because no ignore entry exists for it at all. The
tracked-but-ignored set today:

- `.idea/.idea.NumbersMaze.godot.dir/.idea/` (5 tracked files:
  `.gitignore`, `gradle.xml`, `indexLayout.xml`, `misc.xml`, `vcs.xml` —
  JetBrains nested workspace metadata added to the index on 2023-01-23,
  commit ab0abfc)
- `text/changelog.txt` (1 file; generated by `./update-changelog.sh` from git
  log + `text/changelog.prev*.txt`, matches the `text/.gitignore` entry
  `/changelog.txt`)

Root causes:

1. No `AGENTS.md` exists at the repo root.
2. `.gitignore` omits the Godot editor cache directory `.godot/` — the only
   missing pattern; the committed `.godot/` cache (392 files) therefore sits
   tracked with no ignore coverage at all.
3. Stale index entries for the nested `.idea` files: they were indexed on
   2023-01-23, before the `/.idea/` pattern landed on 2023-06-10
   (commit f55d9ff) — `git check-ignore --no-index -v` attributes each match
   to `.gitignore:16:/.idea/` (git ignores a directory as a whole, so the
   root `.idea/` pattern covers everything beneath it).
4. A stale ignore entry contradicting a recorded decision:
   `text/.gitignore`'s `/changelog.txt` entry predates the developer's
   deliberate re-track of the generated changelog — ce0dea4 (2024-12-14,
   "Add changelog file to track project history") re-added the file 3.5
   years after d6c96a7 (2021-02-16, "Don't track generated file") untracked
   it; the tracked state is the operative intent and the ignore entry is
   what is stale.

## Requirements

- R-1: `AGENTS.md` SHALL exist at the repo root as a compact instruction file
  for future OpenCode sessions.
- R-2: `AGENTS.md` SHALL contain only high-signal, repo-specific guidance —
  no generic software advice, long tutorials, exhaustive file trees, obvious
  language conventions, or speculative claims.
- R-3: Every factual claim in `AGENTS.md` SHALL be verifiable against repo
  sources (config, scripts, code — executable sources of truth preferred over
  prose).
- R-4: `AGENTS.md` SHALL cover exact developer commands (especially
  non-obvious), focused verification steps, required command order where it
  matters, architecture not obvious from filenames, toolchain/testing/setup
  quirks, and references to existing instruction sources that matter.
- R-5: `AGENTS.md` SHALL use short sections and bullets.
- R-6: `.gitignore` SHALL ignore the Godot editor cache directory `.godot/`.
- R-7: Ignore entries SHALL be effective: no tracked file matches an active
  ignore pattern. Achieved by untracking `.godot/` and the nested `.idea`
  workspace files, and by removing the stale `text/.gitignore` entry
  `/changelog.txt` (the generated changelog stays tracked per ce0dea4).
- R-8: `AGENTS.md` SHALL state the post-change ignore state accurately (the
  cache bullet may not claim `.godot/` is committed once it is untracked).

## Approach

1. Keep the drafted `AGENTS.md` (authored under dispatch #1 on
   `feature/agents-md`); revise the editor-cache bullet to the post-change
   state and the export-filter bullet to the verified per-file filters
   (main presets ship `*.txt, *.json, *.bbcode`; the TV preset ships
   `*.txt, *.json` only — `.bbcode` game text does not ship in TV exports).
2. `.gitignore`: add `.godot/`. No other pattern edit in the root file:
   `/.idea/` already covers the nested subtree by directory-match semantics.
   In `text/.gitignore`, remove the stale `/changelog.txt` entry — it
   contradicts the developer's deliberate 2024-12 re-track (ce0dea4).
3. Untrack: `git rm -r --cached .godot .idea/.idea.NumbersMaze.godot.dir`
   (index-only; working-tree files stay on disk; git history preserves the
   removed tip content). `text/changelog.txt` stays tracked.
4. Validate the spec (fresh-context dispatch), then implement, commit as one
   squashed commit, open the PR. Merge is human-only.

## Impact

- Consumers: future OpenCode sessions (`AGENTS.md` auto-loads); contributors
  reviewing diffs (cache churn stops appearing in `git status`); IDE users
  (nested workspace metadata becomes local-only).
- Runtime: none. `text/changelog.txt` stays tracked and ships in exports as
  before; `./update-changelog.sh` keeps regenerating it and the regenerated
  file shows in `git status` as a normal tracked modification.
- Risk: untracking removes the 4.x cache and IDE files from the repo **tip**
  only — content remains in git history and on local disk; a fresh clone
  regenerates caches with the correct (3.x) editor. Reversible: the entries
  can be re-added from history if ever needed.
- Blast radius: repo-local; no code paths, no dependency, no credential, no
  deployment surface.

## Edge cases

- A developer who opens the project with Godot 4.x after this change
  regenerates `.godot/` — it now stays untracked (ignored), so the churn is
  invisible to `git status`; the `AGENTS.md` engine warning remains the
  guard against conversion damage.
- Instrument sequence is fixed: edit ignores → untrack → verify
  (`git ls-files -i -c --exclude-standard` must run after all untracks and
  the `text/.gitignore` edit).
- `text/changelog.txt` regeneration after new commits is expected and safe;
  the file is tracked, so regenerated content shows as a normal
  modification.
